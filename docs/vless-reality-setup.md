# VLESS + Reality на VPS

> Этот документ фиксирует описание проекта из исходного материала. Он не является готовым к запуску Ansible-комплектом: содержимое перечисленных ниже playbook, шаблонов и скрипта в исходном материале отсутствовало.

## Архитектура

Клиент устанавливает соединение с VPS по TLS 1.3 с использованием VLESS + Reality (Xray-core). Для SNI и destination в исходном описании указан домен-маска, по умолчанию `www.cloudflare.com`.

## Параметры из исходного описания

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `vps_hostname` | Имя хоста VPS | `my-vps` |
| `vps_timezone` | Часовой пояс | `Europe/Moscow` |
| `xray_port` | Порт VLESS + Reality | `443` |
| `xray_sni` | SNI | `www.cloudflare.com` |
| `xray_dest` | Destination | `www.cloudflare.com:443` |
| `ssh_port` | Порт SSH | `22` |

В исходном описании также перечислены варианты SNI/destination: `www.cloudflare.com:443`, `www.samsung.com:443`, `www.apple.com:443`, `www.microsoft.com:443`. Это примеры, а не гарантия доступности или пригодности домена для конкретного VPS и клиента.

## Заявленные требования и поведение

- Ansible 2.9 или новее.
- Коллекции `community.general` и `ansible.posix`.
- По описанию, первый запуск должен создавать UUID, ключи X25519 и Short ID и сохранять учетные данные на VPS в `/etc/xray/credentials.yml`; последующие запуски должны использовать сохранённые значения.
- Для получения клиентской ссылки в перечне файлов указан скрипт `scripts/get-connection-link.sh`.
- Для смены SNI/destination исходный материал предлагает изменить `xray_sni` и `xray_dest` в `group_vars/all.yml`, применить тег `xray` и заново получить ссылку.
- Для диагностики в исходном описании предложены проверки UFW, состояния сервиса Xray и журнала systemd.
- Для повышения производительности упоминается BBR.

Эти пункты пересказывают исходное описание. Они не подтверждены запуском playbook, поскольку сами файлы конфигурации не были приложены.

Совместимость зависит от версии клиента и параметров конфигурации.

## Безопасность

- Не публикуйте `/etc/xray/credentials.yml`: исходное описание указывает, что в нём находится приватный ключ.
- Предусмотрите резервную копию учетных данных с ограниченным доступом. Без приватного ключа существующие клиентские настройки могут перестать работать.
- Проверьте правила firewall и сохраните доступ по SSH до применения изменений.
- Используйте ПО и сетевые настройки в соответствии с законодательством, применимым к вашей ситуации.
